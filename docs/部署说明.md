# 容器化部署

本项目使用 Next.js `standalone` 输出，通过 Docker 在服务器上常驻运行。定时任务（默认上海时间 17:00 自动生成并发送）依赖容器保持运行。

## 前置条件

- 服务器已安装 Docker 与 Docker Compose（Compose V2：`docker compose`）
- 开放端口 `38471`（或在 `docker-compose.yml` 中改成其它宿主机端口）
- 服务器能访问外网（采集行情/公告/新闻，以及 SMTP 发信）

## 一键启动

在项目根目录：

```bash
mkdir -p data
# 容器内进程为 uid 1001，需保证可写
sudo chown -R 1001:1001 data

# 可选：指定对外访问地址（邮件正文若带链接会用到）
export APP_ORIGIN=http://你的服务器IP或域名:38471

docker compose up -d --build
```

浏览器打开：`http://服务器地址:38471`。

查看日志：

```bash
docker compose logs -f
```

停止：

```bash
docker compose down
```

## 数据持久化

| 宿主机路径 | 容器路径 | 内容 |
| --- | --- | --- |
| `./data` | `/app/data` | `settings.json`（SMTP/收件人）、`reports/`、`scheduler.json` |

不要把 `data/` 提交进 Git。更换或重建镜像时，只要保留该目录，报告与发信设置不会丢。

首次部署后请在页面「发信设置」中配置 SMTP 与收件人，并发送一封测试信。

## 仅用 Docker 构建 / 运行（不经过 Compose）

```bash
docker build -t jiaokong-opinion-daily .
docker run -d --name jiaokong-opinion-daily \
  -p 38471:38471 \
  -e TZ=Asia/Shanghai \
  -e APP_ORIGIN=http://你的服务器IP:38471 \
  -v "$(pwd)/data:/app/data" \
  jiaokong-opinion-daily
```

## 时区与定时

容器默认 `TZ=Asia/Shanghai`。调度器按该时区判断「今天」与 17:00 自动发信。改调度时间可在「发信设置」中调整，写入 `data/settings.json`。

## 反向代理（可选）

若前面还有 Nginx / Caddy，把 HTTPS 反代到 `127.0.0.1:38471`，并把 `APP_ORIGIN` 设为对外的 `https://域名`。

## 更新版本

```bash
git pull
docker compose up -d --build
```

`data/` 卷会保留，无需重新配置 SMTP（除非你主动清空）。
