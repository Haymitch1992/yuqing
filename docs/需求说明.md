# 交控科技舆情日报需求说明

| 项 | 内容 |
| --- | --- |
| 文档版本 | 1.0 |
| 日期 | 2026-10-31 |
| 监控主体 | 交控科技股份有限公司（688015） |
| 依据 | 《交控科技股份有限公司舆情报告》（2026-10-30 至 2026-10-31），以及「每天生成、先预览、再发到指定邮箱」的使用方式 |

## 1. 要解决的问题

投关或董办人员需要在每个自然日结束后知道三件事：公司股价收在哪里、当天披露了什么、公开报道怎么写。结果要形成一份能读完的日报，并由人看过之后，再发到指定邮箱。

样本报告来自商业舆情产品，覆盖网站、APP、论坛、贴吧共 95 条，并给出情感、渠道、媒体和热度。自建系统沿用这份报告的章节和「数字必须能回溯」的要求。渠道覆盖按公开可获得的数据源落地，不要求条数与该商业报告逐条对齐。

## 2. 使用者与场景

使用者是负责交控科技这一家公司舆情的内部人员。本期只有一个监控主体，没有登录账号，也没有多公司切换。

三个场景：

1. 每个上海时间工作日的晚间，系统生成当天草稿，人打开预览，确认后发给指定同事。
2. 漏掉的日期可以补生成，范围是今天以及过去一年。
3. 发信前用一封测试信确认 SMTP 可用。

## 3. 本期范围

本期要交付：

- 按上海时区的自然日生成草稿
- 行情、上交所公告、标题强相关的公开新闻
- 同题归并、情感与事件分类、概况数字与明细一致
- 页面预览
- 把当前报告导出为 Word，三章和统计数字与预览页相同
- 预览之后发到指定邮箱
- 发信参数和每天生成时间可配置

本期不交付：

- 今日头条、天眼查、雪球、贴吧的全量条数。网易、同花顺、腾讯自选股只采公开列表里的强相关标题，不与样本条数对齐
- 与样本报告 95 条、负面 57 条对齐
- 微博、微信、短视频
- 可比公司对照
- Word 导出
- 人工改情感后自动重算
- 多公司、账号权限、自动发信

## 4. 报告内容

报告标题为「交控科技股份有限公司舆情日报」。每份报告固定包含报告日、证券代码、生成时间，以及下面三章。

### 4.1 行情概况

取报告日当天或之前的最后一个交易日。非交易日仍出报告，行情沿用该交易日，并在文中写明截止日。

必须给出：

- 近 20 个交易日收盘价走势
- 收盘价、涨跌幅、涨跌额、成交量、最高价、成交额、最低价、换手率
- 市盈率（静）、市盈率（动）、市净率、量比
- 总市值、流通市值、总股本、流通股、每股净资产、股息率

最新交易日的字段来自腾讯行情。若补生成的是更早的日期、且该日不是最新交易日，至少给出开高低收和涨跌；估值字段留空并说明原因。

样本日 2026-10-31 是周六，行情截止日应为 2026-10-30。

### 4.2 舆情概况

用同一批结果写出：

- 传播条数、归并后的事件数、负面事件数、当日主基调
- 热度最高的事件：来源、标题、同题条数
- 情感分布：正面、负面、中性的事件数和占比，合计等于事件数
- 渠道分布、媒体分布：按条数统计，合计等于传播条数

主基调取事件情感的众数。两类情感数量相同则写中性。

### 4.3 舆情明细

明细按事件列出，不把同题转载铺成多行正文。每行包含时间、标题、情感、事件类型、来源、热度，标题链到原文。热度大于 1 时，可展开同题的其余条目。

负面明细是全部事件里情感为负面的子集，使用同一套数据。

正文只保留摘要和链接，不把全文贴进报告。

### 4.4 数据说明

每份报告都要写明采集边界：公告来自上交所当日披露，行情来自腾讯行情。新闻来自东方财富搜索，以及网易搜索、同花顺个股资讯、腾讯自选股个股资讯中标题含「交控科技」或「688015」的结果。今日头条、天眼查、雪球不在本次采集内。某一路取数失败时，报告仍可生成，并在文首列出失败项。行情、公告和全部新闻源都失败时，不保存空报告。

## 5. 口径

| 名称 | 定义 | 用在哪里 |
| --- | --- | --- |
| 强相关 | 标题含「交控科技」或「688015」 | 新闻是否入报。只在正文里提到公司名的名单稿不入报 |
| 传播条数 | 强相关公告加新闻的条数 | 概况第一句、渠道表、媒体表 |
| 事件 | 同一事件类型下、标题归一后判为同题的一簇 | 明细的一行 |
| 热度 | 该簇内的条数 | 明细和高峰句。热度不是阅读量或转发量 |
| 首发 | 簇内发布时间最早的一条；时间相同则公告优先 | 明细标题和摘要 |
| 情感 | 打在事件上，不随转载站点改变 | 情感表、负面清单、主基调 |

情感和事件按标题规则判定，顺序如下：

| 标题命中 | 事件 | 情感 |
| --- | --- | --- |
| 留置 | 治理 | 负面 |
| 董事长，且出现辞或离任 | 治理 | 负面 |
| 减值 | 财务 | 负面 |
| 季报、季度报告、净利润、营收、业绩 | 业绩 | 标题另含利空、下滑、下降、亏损等为负面，否则中性 |
| 总经理、聘任 | 人事 | 标题另含利空类词为负面，否则中性 |
| 募投、募集资金 | 募投 | 中性 |
| 中标 | 经营 | 正面 |
| 专利 | 研发 | 正面 |
| 利空、下滑、下降、亏损、跌停、减持、立案、诉讼、仲裁、拖欠、暴跌 | 其他 | 负面 |
| 增长、上涨、预增、回购、增持、扭亏 | 其他 | 正面 |
| 其余 | 其他 | 中性 |

同一簇内若有多条情感，取多数；负面不少于其他两类时，整簇记为负面。专利授权保持正面，不因转载到不同网站而改判。

## 6. 功能需求

### 6.1 生成

- 默认每天 20:30（上海时间）生成当天草稿。服务进程在这个时间点之后仍在运行时，当天尚未生成则补生成一次。
- 定时生成失败后，至少间隔 10 分钟再试。
- 首页可以选择今天或过去一年内的日期手动生成。
- 同一天已有报告时，再次生成直接打开已有报告。
- 尚未发送的报告可以重新采集，重新采集后需要再次预览才能发送。
- 已经发送的报告不能被重新采集覆盖。

### 6.2 预览

- 列表展示报告日、事件数、负面事件数、状态、生成时间。
- 状态只有三种：待预览、待发送、已发送。
- 打开报告页即完成预览，状态从待预览变为待发送。
- 预览页完整展示第 4 节的三章。取数失败的说明出现在正文之前。
- 预览页和列表都可以导出 Word。文件包含同一份统计结果：行情折线、行情表、情感、渠道、媒体，以及全部事件和负面事件。标题链到原文。收盘价图与预览页是同一条折线。

### 6.3 发送

- 未完成预览时，不能发送。
- 发送前打开发送确认，收件地址可改，默认带上已保存的全部收件人。多个地址用换行、逗号或分号分开，同一封信发给全部地址。
- 未配置 SMTP 时，确认框说明原因并进入发信设置，不发出邮件。
- 发送成功后记录发送时间和收件人，状态变为已发送。同一份报告允许再发一封。
- 邮件包含综述、高峰句、行情摘要、事件表，以及回到预览页的链接。同一份 Word 作为附件发出，内容和「导出 Word」一致。
- 发信设置包括：是否开启定时、生成时间、收件人（可以多个）、SMTP 主机、端口、SSL、账号、授权码、发件人地址。
- 授权码留空保存时，保留原来的授权码。
- 提供测试信。测试信不写入报告发送记录。

## 7. 非功能需求

- 时区一律使用上海时间。报告日是自然日，不是交易日。
- 定时依赖报告服务进程持续运行。进程不在，当天不会自动出草稿。
- 授权码只保存在服务器本地的 `data/settings.json`，不进入代码仓库，接口不回传授权码明文。
- 入库和成稿保存标题、时间、来源、链接和摘要。
- 桌面和约 390 像素宽的手机都能完成生成、预览、打开发送确认和填写设置。表格可以横向滚动。

## 8. 验收

用 2026-10-30 和 2026-10-31 两天验收。搜索结果会变化，验收看规则是否成立，不看是否凑满样本报告的 95 条。

| 编号 | 验收 |
| --- | --- |
| AC-1 | 2026-10-31 的行情截止日是 2026-10-30，收盘价、涨跌幅与腾讯行情该日收盘一致 |
| AC-2 | 2026-10-31 的明细包含上交所《关于董事长被留置并辞任的公告》，该事件为负面、类型为治理 |
| AC-3 | 2026-10-31 同时包含三季报、计提减值、变更总经理、募投结项。减值为负面，三季报标题本身为中性、类型为业绩 |
| AC-4 | 2026-10-30 的明细包含董事长被留置的公开新闻，且这些事件为负面 |
| AC-5 | 情感表的事件数之和等于事件总数；渠道表、媒体表的条数之和等于传播条数 |
| AC-6 | 未打开预览时调用发送，被拒绝 |
| AC-7 | 未配置 SMTP 时，预览页可以打开发送确认，但不能把邮件发出去 |
| AC-8 | 已发送的报告不能重新采集覆盖 |
| AC-9 | 标题不含公司名、只在正文名单里出现代码的稿件不进入明细 |
| AC-10 | 已生成的报告可以下载 Word。文件含「一、行情概况」「二、舆情概况」「三、舆情明细」，其中的传播条数和事件数与预览页一致 |
| AC-11 | 发送日报时，收件人收到的邮件带有与预览一致的 Word 附件 |

## 9. 后续需求

下面这些不进入本期验收。需要单独立项。

| 顺序 | 需求 | 说明 |
| --- | --- | --- |
| 1 | 人工复核 | 改某一事件的情感或类型后，概况、负面清单和邮件一起重算。已发送版本保留发送当时的快照 |
| 2 | 新闻源扩展 | 同花顺公开资讯已接入。后续可再加财联社快讯。新来源只加采集，不改统计定义 |
| 3 | 雪球讨论 | 作为论坛渠道的补充。公开页当前打不开。允许漏采，不作为条数验收 |
| 4 | 可比公司 | 样本报告中该项为「暂未设置」。有同业名单后再增加对照节 |
| 5 | 热榜告警 | 公司名进入今日头条、贴吧、微博热榜时另发提醒。热榜提醒不是日报的传播条数 |

商业报告里的今日头条条数、天眼查条数、雪球条数和未具名的贴吧条数，不作为验收目标。腾讯自选股只按公开资讯列表采集，不追求与样本条数一致。
